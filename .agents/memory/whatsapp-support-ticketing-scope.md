---
name: WhatsApp support ticketing scope
description: Product boundaries for VisiteCRM's human-support tickets.
---

Create tickets only through the existing human-handoff paths. Do not backfill historical conversations. Keep ticket lifecycle separate from chatbot conversation status. Multiple WhatsApp numbers and full real-time updates remain deferred unless the user expands scope.

**Why:** the user approved an initial ticketing scope centered on human handoffs and explicitly deferred historical backfill, multiple numbers, and full real-time behavior.

**How to apply:** preserve these boundaries when extending WhatsApp support; ask for explicit scope expansion before adding the deferred behavior.
