---
name: Agency backup export format
description: Durable decisions behind the full-agency JSON backup export (GET /api/tenants/backup/export), relevant to any future import/restore work or to extending backup coverage.
---

- `meta.formatVersion` is a plain integer bumped on any breaking shape change (added/removed/renamed top-level section, changed nesting). An importer should refuse or branch on unknown/older versions rather than assume the current shape.
- Nested embedding (e.g. reservations carrying their passengers, orders carrying their items) mirrors how other exports in this codebase already nest related rows — keep new sections consistent with that rather than inventing flat sibling arrays for data that's 1:many owned by a parent already in the export.
- The export excludes all auth/payment secrets (Clerk IDs, OAuth tokens, gateway keys/webhook secrets, payment tokens) and single-use bearer tokens on otherwise-durable records (invite/invitation acceptance tokens — the record itself is kept, only the token field is stripped), plus ephemeral tracking/fingerprint fields (IP, user-agent, cookie IDs, live location pings). A restore flow must have the agency reconnect those integrations and re-issue any pending invites rather than expect secrets in the JSON.
- Coverage scope is *every* durable, tenant-owned, non-secret, non-log table — not just the entities named in a feature spec. This includes tables owned by a child record (e.g. per-client or per-trip content) rather than the tenant directly, and any table a referenced-by-id field on an already-included record points to. A dangling reference (parent id present, parent table itself absent from the file) is a hard blocker, not a nice-to-have. When a table has a discriminator-typed reference (e.g. a `sellerType` enum paired with a column that can point to different tables depending on the discriminator's value), every value the discriminator can take must have its target table included. When adding any new tenant-owned table anywhere in the product, ask whether it belongs in this export before assuming it's out of scope just because it wasn't named explicitly.
- Deliberately out of scope, treated as a stable boundary rather than an oversight: ephemeral/system logs and audit trails (delivery/send logs, execution/attempt logs, notifications, webhooks, sessions), AI-generated/derived insight feeds (not authored source data), the tenant's billing/subscription relationship with the platform itself (plans, invoices, feature flags, usage), and data resynced from a third-party integration where exporting only part of the synced graph would itself create dangling references. Re-evaluate a specific exclusion only if the product turns that table into durable business content the agency directly authors, or a completeness review flags it as such with reasoning.
- Every array is fetched via cursor pagination (`createdAt`/equivalent monotonic column + `id`) in fixed-size batches and streamed with backpressure, matching the existing trips-export pattern — don't materialize a whole tenant's data in memory when extending this.
